# Manual interactive Windows acceptance — PortableApps mode only

Run these on a throwaway Windows 10/11 x64 test user account, ideally with an installed nonportable FreeCrawl copy **and a backup**. Never point recovery tooling at another person's profile or production computer. Note each test result as PASS/FAIL with screenshots and ProcMon traces; these tests cannot be verified merely from headless GitHub Actions.

1. Extract the ZIP to a path with spaces and Unicode characters, for example `D:\Tools\SEO 工具\FreeCrawlSEOToolPortable`. Launch only the root `FreeCrawlSEOToolPortable.exe` from Explorer. Verify window, crawl, persistence and restart.
2. Create a crawl, change theme/settings, save projects, restart, inspect `Data/Profile/preferences.json`, `Data/Profile/projects`, `Data/Session`, `Data/Logs`, and the scratch SQLite/WAL files. Ensure the app remains functional after multiple open/close cycles.
3. Run a simple JS-render crawl that triggers Playwright install, verify Chromium downloads under `Data/Profile/playwright-browsers`, then relaunch and render offline using the saved browser. Check the Playwright `chromium` and `chromium_headless_shell` subdirectories.
4. Test native exports explicitly saved to Documents/Downloads; these are user-directed exports and intentionally may remain outside Data. Do not mistake them for unnoticed app traces.
5. Use Process Monitor filtered by executable names **FreeCrawl SEO Tool.exe** (and actual browser child names) to inspect writes in `%APPDATA%`, `%LOCALAPPDATA%`, `%PROGRAMDATA%`, `%TEMP%`, HKCU, Startup, Start Menu and Windows Notifications. Record actual path and initiator; distinguish Windows cache from application-owned persistent state. Any newly discovered app-owned location needs a narrowly scoped solution and a separate data-safety test.
6. Enable and trigger real notifications, click them, close/reopen the tray window, end the full application process, restart Explorer. Observe toast delivery, click activation and shell registry entries without deleting them. User-facing notification handling remains **NOT YET VERIFIED** until this test passes.
7. Test launch with a second instance while the first is still open. Upstream `requestSingleInstanceLock()` should direct a second launch to the current application window. Validate its multi-project window behavior and CLI argument forwarding.
8. Verify a pre-existing **installed** FreeCrawl user profile remains untouched, including existing same-name shortcuts and preferences. Launch installed and portable versions in either order; record any unintended AUMID/notification identity conflict.
9. Move the entire portable folder to another writable drive or Unicode path, relaunch, open manually saved projects and test Playwright browser path. Recent absolute project paths may need user action.
10. Force-kill the portable app mid-crawl, reopen it and check SQLite crash recovery and data integrity. Then test copied ZIP upgrade while app is closed and confirm Data and existing empty directory trees are untouched.
11. Install the generated community `.paf.exe` to an empty directory; close the app, create files and nested **empty directories** under Data, then reinstall and upgrade to a newer build. Check all Data survives, including empty folders and any existing recovery manifests. If installer removes Data, this is an installer failure — stop deployment and inspect the shared Package Builder.
12. Move or uninstall the portable package and check installed-app shortcuts/registry entries; note Windows-managed shell history/cache may remain. The launcher neither registers nor removes shell items itself.
13. Verify the built launcher EXE PE architecture, icons, appinfo metadata, ZIP CRC, actual installer execution and exit code, install destination and SHA256SUMS. Test rollback only after backing up full Data; newer project DB schemas may not be backward-compatible.

**Evidence classification:** Static source audit ≠ Windows compile ≠ GUI run ≠ recovery test ≠ user-confirmed portability. Keep separate run logs and mark all untested categories NOT YET VERIFIED.
